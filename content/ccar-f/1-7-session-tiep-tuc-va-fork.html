Domain 1: Agentic Architecture & Orchestration·Task 1.7

Tiếp tục, fork hay bắt đầu lại một phiên làm việc

Quay lại phiên đã đặt tên bằng --resume, thử hai hướng bằng fork_session, và khi nào nên mở phiên mới kèm bản tóm tắt.

Đọc xong bạn nắm được

  • Đặt tên phiên và quay lại đúng phiên đó bằng --resume
  • Dùng fork_session để thử hai cách làm từ cùng một kết quả phân tích
  • Báo cho phiên được tiếp tục biết file nào đã thay đổi
  • Chọn giữa tiếp tục phiên cũ và mở phiên mới kèm bản tóm tắt

Một phiên làm việc (session) với Claude Code hay Agent SDK là toàn bộ cuộc trò chuyện: các tin nhắn, các lần gọi tool và kết quả. Việc lớn thường kéo dài qua nhiều ngày, nên bạn sẽ cần quay lại phiên cũ, hoặc tách một phiên ra để thử hướng khác.

Bài này giúp bạn trả lời: khi nào nên tiếp tục phiên cũ, khi nào nên tách nhánh, và khi nào nên bỏ phiên cũ để bắt đầu lại?

Ví dụ xuyên suốt: điều tra trang thanh toán bị chậm

Lan được giao tìm nguyên nhân trang thanh toán của một trang bán vé xem phim tải mất 6 giây vào giờ cao điểm.

  • Thứ Hai: Lan mở Claude Code, nhờ Claude đọc code, xem log, chạy vài truy vấn. Cuối ngày Claude đã khoanh vùng: chậm ở phần tính giá khuyến mãi, mỗi lần tải trang gọi cơ sở dữ liệu 40 lần.
  • Thứ Ba: Lan muốn làm tiếp từ chỗ đó. Nhưng tối qua một đồng nghiệp đã sửa hai file trong phần khuyến mãi.

Đặt tên phiên và quay lại bằng --resume

Claude Code cho phép đặt tên phiên để dễ tìm lại. Đặt tên lúc mở phiên, hoặc đổi tên giữa chừng bằng lệnh /rename:

claude -n checkout-cham

Hôm sau, quay lại đúng phiên đó bằng tên:

claude --resume checkout-cham

Theo tài liệu Claude Code, phiên được tiếp tục sẽ có lại toàn bộ lịch sử: tin nhắn, các lần gọi tool và kết quả. Claude nhớ hết những gì đã phân tích hôm qua, không phải đọc lại code từ đầu.

Trong Agent SDK, bạn tiếp tục một phiên bằng cách truyền mã phiên vào tuỳ chọn resume. Mã phiên lấy từ field session_id trong kết quả của lần chạy trước.

Báo cho phiên cũ biết cái gì đã thay đổi

Đây là chỗ dễ sai. Lịch sử phiên của Lan có kết quả đọc file từ hôm thứ Hai. Nhưng hai file đã bị sửa từ tối qua. Nếu Lan chỉ gõ "làm tiếp đi", Claude sẽ suy luận dựa trên nội dung file cũ còn nằm trong lịch sử, vì nó không tự biết file đã đổi.

Cách làm đúng là nói rõ cái gì đã đổi, để Claude chỉ đọc lại đúng chỗ đó:

Lưu ý: tối qua Minh đã sửa promo/calculator.ts và promo/rules.ts.
Đọc lại hai file này rồi kiểm tra kết luận hôm qua còn đúng không.

Như vậy Claude không phải dò lại cả codebase, mà cũng không làm việc trên thông tin đã cũ.

Bẫy đề

Đề hay có đáp án "tiếp tục phiên cũ, Claude sẽ tự nhận ra file đã thay đổi". Sai: kết quả đọc file trong lịch sử là bản chụp lúc đọc, Claude không tự biết file đã bị sửa sau đó. Phải báo cho nó biết file nào đã đổi.

Fork để thử hai hướng

Thứ Ba, Lan có hai hướng sửa:

  1. Thêm bộ nhớ đệm (cache) cho bảng khuyến mãi.
  2. Viết lại truy vấn để gộp 40 lần gọi thành 1.

Cả hai đều cần dựa trên kết quả phân tích hôm thứ Hai. Lan không muốn thử hướng 1 xong rồi phải gỡ ra mới thử được hướng 2 trong cùng một phiên, vì lịch sử sẽ lẫn lộn hai hướng.

Lúc này dùng fork: tách phiên thành hai nhánh độc lập, cùng bắt đầu từ một điểm chung.

claude --resume checkout-cham --fork-session

Trong Agent SDK là tuỳ chọn fork_session (Python) hay forkSession (TypeScript), dùng cùng với resume. Theo tài liệu, phiên fork bắt đầu với bản sao lịch sử của phiên gốc rồi đi theo hướng riêng. Nó có mã phiên mới, còn phiên gốc giữ nguyên.

Một lưu ý từ tài liệu: fork tách lịch sử cuộc trò chuyện, không tách file trên máy. Hai nhánh cùng sửa một thư mục thì vẫn đụng nhau.

Tiếp tục phiên cũ cũng vậy: tài liệu Agent SDK viết rõ phiên lưu cuộc trò chuyện, không lưu file trên máy. Muốn đưa file về bản cũ thì bật file checkpointing: SDK sao lưu file trước khi các tool Write, Edit hay NotebookEdit sửa nó, rồi bạn quay lại (rewind) một điểm đã lưu. Vì vậy khi tiếp tục phiên, file trên máy vẫn là bản hiện tại dù lịch sử phiên còn nội dung cũ; phiên không tự đưa file về lại bản cũ, và đó không phải lỗi. Checkpointing chỉ theo dõi file sửa qua Write, Edit, NotebookEdit, không theo dõi thay đổi do lệnh Bash như sed -i.

Tiếp tục phiên cũ hay mở phiên mới

Giả sử thay vì hai file, đồng nghiệp đã viết lại gần hết phần khuyến mãi. Phần lớn kết quả đọc file trong lịch sử giờ đã sai. Tiếp tục phiên cũ lúc này còn tệ hơn bắt đầu lại, vì Claude sẽ bị kéo bởi một đống thông tin cũ.

Cách tốt hơn là mở phiên mới, và đưa vào một bản tóm tắt có cấu trúc những gì vẫn còn đúng:

Mục tiêu: tìm nguyên nhân trang thanh toán chậm 6 giây giờ cao điểm.
Đã biết: chậm ở phần tính giá khuyến mãi; trước khi sửa, mỗi lần tải trang
gọi cơ sở dữ liệu 40 lần.
Đã thay đổi: phần promo/ vừa được viết lại hoàn toàn, chưa phân tích lại.
Việc cần làm: đo lại số lần gọi cơ sở dữ liệu với code mới.

Trong đề chọn gì

Câu hỏi về quay lại việc sau khi code đã thay đổi: nếu chỉ vài file đổi, chọn tiếp tục phiên và báo đúng file nào đã đổi. Nếu kết quả tool cũ không còn dùng được, chọn mở phiên mới kèm bản tóm tắt, vì cách này đáng tin hơn tiếp tục với kết quả cũ.
