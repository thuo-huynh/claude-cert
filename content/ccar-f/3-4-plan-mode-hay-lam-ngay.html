Domain 3: Claude Code Configuration & Workflows·Task 3.4

Khi nào dùng plan mode, khi nào làm ngay

Nhận ra việc nào cần plan mode để khảo sát và lên kế hoạch trước, việc nào nên làm ngay, và dùng subagent Explore để giữ context chính gọn.

Đọc xong bạn nắm được

  • Chọn plan mode cho thay đổi lớn, nhiều cách làm, có quyết định kiến trúc
  • Chọn làm ngay cho thay đổi nhỏ, rõ phạm vi
  • Kết hợp lên kế hoạch bằng plan mode rồi làm theo kế hoạch đã duyệt
  • Dùng subagent Explore cho giai đoạn khảo sát in ra nhiều để context chính không bị đầy

Nhờ Claude Code sửa code, bạn có hai cách: bảo nó làm luôn, hoặc bảo nó khảo sát và đưa kế hoạch cho bạn duyệt trước. Lên kế hoạch cho việc nhỏ thì phí thời gian. Làm luôn một việc lớn thì dễ phải đập đi làm lại.

Bài này giúp bạn trả lời: nhìn vào một yêu cầu, làm sao biết nên lên kế hoạch hay làm ngay?

Ví dụ xuyên suốt: website đặt tour du lịch

Nhóm bạn làm website đặt tour. Tuần này có ba việc:

  1. Thêm một điều kiện trong hàm validateBooking: số khách phải từ 1 trở lên.
  2. Khách báo lỗi khi đặt tour Đà Lạt. Log có stack trace chỉ thẳng vào dòng 88 của tinhGiaTour.ts: chia cho 0 khi tour chưa có giá trẻ em.
  3. Chuyển từ cổng thanh toán cũ sang cổng mới. Code thanh toán cũ được gọi ở khoảng 60 file. Cổng mới có hai cách tích hợp: chuyển khách sang trang của cổng, hoặc nhúng form vào trang mình. Hai cách cần hạ tầng khác nhau (cách nhúng form cần thêm chứng chỉ bảo mật và webhook).

Plan mode là gì

Plan mode là chế độ Claude khảo sát và đề xuất thay đổi mà chưa sửa gì. Theo tài liệu Claude Code, trong plan mode Claude đọc file, chạy lệnh để tìm hiểu, viết ra một kế hoạch, nhưng không sửa code của bạn cho tới khi bạn duyệt kế hoạch.

Cách bật:

  • Nhấn Shift+Tab để đổi chế độ cho tới khi thanh trạng thái hiện plan mode.
  • Gõ /plan trước một câu lệnh để chỉ câu đó chạy ở plan mode.
  • Mở Claude Code bằng claude --permission-mode plan.

Khi kế hoạch xong, Claude đưa cho bạn xem và hỏi làm tiếp thế nào: duyệt và cho Claude làm, duyệt nhưng bạn tự duyệt từng lần sửa, hoặc tiếp tục lên kế hoạch. Muốn sửa kế hoạch trước khi duyệt thì nhấn Ctrl+G để mở nó trong trình soạn thảo.

Ích lợi chính: bạn thấy hướng đi trước khi code bị đụng tới. Nếu kế hoạch sai, bạn chỉ mất vài phút đọc, không phải hoàn tác vài chục file.

Khi nào dùng plan mode

Có bốn dấu hiệu cho thấy một việc cần plan mode:

Dấu hiệuTiếng Anh trong đềTrong ví dụ
Thay đổi trên diện rộnglarge-scale changesCode thanh toán nằm ở khoảng 60 file
Có nhiều cách làm đều hợp lýmultiple valid approachesChuyển trang hay nhúng form
Có quyết định về kiến trúcarchitectural decisionsHai cách cần hạ tầng khác nhau
Sửa nhiều file liên quan nhaumulti-file modificationsĐổi cách gọi thanh toán kéo theo đổi luồng đặt tour

Việc 3 có đủ cả bốn. Làm luôn thì Claude sẽ tự chọn một cách tích hợp, sửa vài chục file, rồi tới lúc phát hiện cách đó không hợp hạ tầng hiện tại thì đã muộn. Plan mode giúp tránh đúng chuyện phải làm lại tốn kém này (costly rework).

Khi nào làm ngay

Làm ngay (direct execution) hợp với việc nhỏ, rõ phạm vi: bạn biết sửa gì, sửa ở đâu, và chỉ có một cách hợp lý.

  • Việc 1: thêm một điều kiện vào một hàm. Không có gì để khảo sát.
  • Việc 2: stack trace đã chỉ đúng dòng. Claude đọc đoạn code đó, tìm nguyên nhân, sửa. Kể cả khi bạn chưa từng đọc module này, lỗi đã được khoanh vùng thì cứ đi thẳng vào chỗ stack trace chỉ.

Việc cơ học, đã rõ phải làm gì và chỉ có một cách đúng, thì cũng làm ngay, kể cả khi đụng nhiều file. Ví dụ đổi tên hàm tinhGia thành tinhGiaTour ở mọi nơi gọi nó: không có gì để chọn, nên thêm pha phân tích và đề xuất chỉ tốn thời gian. Nhiều file một mình chưa nói lên việc khó. Ngược lại, "cải thiện xử lý lỗi cho cả module đặt tour" là việc mở: phải khảo sát, quyết chỗ nào cần bắt lỗi, báo lỗi ra sao. Đó mới là chỗ chia pha phân tích, đề xuất rồi mới làm có ích.

  1. Thay đổi lan ra nhiều file hoặc nhiều module, và có chỗ phải quyết định?Plan mode
  2. Có từ hai cách làm trở lên, cần chọn?Plan mode
  3. Ảnh hưởng tới kiến trúc hay hạ tầng?Plan mode
  4. Còn lạiViệc nhỏ, rõ chỗ sửa, một cách làm: làm ngay

Bẫy đề

Với việc nhỏ như thêm một điều kiện hay sửa lỗi có stack trace rõ, đề hay đưa đáp án "vào plan mode để phân tích ảnh hưởng tới các phần khác" hoặc "bật extended thinking cho chắc". Nghe cẩn thận nhưng chỉ tốn thêm thời gian. Ngược lại, với việc lớn mà đề đã nói rõ là phức tạp, đáp án "cứ làm trước, gặp khó thì chuyển sang plan mode" là sai: độ phức tạp đã biết từ đầu, không phải chờ nó lộ ra.

Lên kế hoạch rồi mới làm

Hai chế độ không loại trừ nhau. Với việc 3, cách hợp lý là:

  1. Bật plan mode. Claude khảo sát code thanh toán đang được gọi ở đâu, liệt kê những luồng bị ảnh hưởng, so sánh hai cách tích hợp.
  2. Bạn đọc kế hoạch, chọn cách tích hợp, sửa kế hoạch nếu cần.
  3. Duyệt kế hoạch. Claude thoát plan mode và bắt đầu sửa code theo đúng kế hoạch đó.

Nói cách khác: dùng plan mode cho phần tìm hiểu, rồi làm ngay cho phần thực hiện.

Subagent Explore cho giai đoạn khảo sát

Khảo sát 60 file thì Claude phải đọc rất nhiều. Nếu tất cả nội dung đó đổ vào cuộc trò chuyện chính, context đầy dần, và tới lúc bắt tay sửa code thì Claude đã quên bớt những gì đọc lúc đầu.

Claude Code có sẵn subagent Explore cho việc này. Theo tài liệu Claude Code:

  • Explore chỉ có tool đọc; Write và Edit bị chặn.
  • Nó dùng để tìm file, tìm code, khảo sát codebase.
  • Nó đọc file trong context riêng của nó và chỉ gửi về bản tóm tắt, nên kết quả khảo sát không chiếm context của cuộc trò chuyện chính.
  • Claude chọn mức kỹ khi gọi nó: nhanh cho tra cứu cụ thể, vừa, hoặc rất kỹ cho phân tích toàn diện.

Trong plan mode, khi cần hiểu codebase, Claude cũng giao phần tìm hiểu cho một subagent có sẵn khác tên là Plan, cũng chỉ có tool đọc, để kết quả khảo sát nằm ở context riêng.

Trong đề chọn gì

Thay đổi lớn, có quyết định kiến trúc: chọn plan mode. Việc nhỏ, rõ chỗ sửa: chọn làm ngay. Giai đoạn khảo sát in ra nhiều làm đầy context trong một việc nhiều bước: chọn subagent Explore để nó tóm tắt lại.
